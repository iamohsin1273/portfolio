04 Promote · flagship case study

Dev → UAT → Prod, the real pipeline.

The customer-portal deployment pipeline I run in production: a Linux Jenkins server driving deployments onto a Windows IIS host over an SMB mount — promoted stage by stage, backed up before every release.

Pre-deploy backup

Context

A customer-facing portal site is promoted across three environments — Dev, UAT, then Prod. UAT → Prod is the promotion that matters: it's the release gate before real users see a change.

What I do

  • Run UAT → Prod promotions on the Jenkins/IIS pipeline
  • Handle direct file uploads and xcopy-based deploys to the Windows server
  • Recycle IIS application pools so new builds take effect
  • Take pre-deployment backups so every release is reversible

What breaks / the runbook

SMB mount availability, app-pool state, and file-lock timing are the usual failure points. The runbook covers backup-first, verify-after, and a clean rollback path to the previous archived release.

What I'd improve

  • Replace xcopy/SMB with a versioned artifact + automated rollback
  • Add health-check gating before the app-pool cutover
  • Codify the Windows host + IIS config in Terraform/Ansible
